# 维护与版本策略

## 版本

- `MAJOR`：任务定义、候选空间、标签 estimand 或主指标发生不兼容变化。
- `MINOR`：新增数据源、公开模型或预注册评估单元，但保留既有结果可重算。
- `PATCH`：实体映射、文献来源、元数据或代码缺陷修正，不改变协议定义。

每个版本必须保存 manifest、数据源访问日期、固定提交/版本、运行环境和变更说明。不能静默覆盖已发布的 split 或 summary。

## 问题与纠错

问题报告至少包含：受影响资源、实体标识、原值、建议值、可核查来源和预期影响。映射修正先进入新 patch 候选，重跑受影响单元并比较主表；若结论方向改变，必须在变更说明中醒目标注。

## 新数据与模型

新增资源先通过许可证、实体映射、重复与来源字段审计；新增模型必须能在相同候选空间、相同 split 和相同强先验下运行。不能只加入作者报告值来替代可比较实验。

## 退役条件

出现以下任一情况时，旧单元标记为 deprecated 而不是删除：官方资源撤回或许可证变化；标识映射不可恢复；来源字段不足以支持原 estimand；更正后无法复现主表。退役单元保留历史 manifest 和原因，但不再进入当前汇总。

## 责任边界

维护者只保证已发布工件按其 manifest 可核验，不保证第三方下载长期可用，也不把数据库未记录配对解释为生物学负例。
